# MES 技术设计

- 前端：React、TypeScript、Vite；后端：NestJS、TypeScript；数据库：PostgreSQL、Prisma。
- 每个请求从 HttpOnly 会话取得租户和角色；服务端按租户及工单指派过滤。写操作使用版本号避免并发覆盖。
- 独立部署自动创建本地管理员，由管理员建立角色账号；成员可凭旧密码修改密码并注销全部会话。办公平台登录不是运行前提。
- 计划、工单、报工、审核和审计均落库。审核在事务内更新报工和工单数量，检查超量并记录审计。
- API 前缀 `/api/v1`；对象使用 UUID；错误为 `{error:{code,message,request_id}}`。入口包括 `/materials`（分页搜索、创建、编辑）、`/boms`、`/plans`、`/orders`、`/orders/:id/reports`、`/reports/:id/review`、`/dashboard`、`/admin/users`。
- 新 BOM 通过 `product_material_id` 和组件 `material_id` 引用物料主数据，同时保存 SKU、名称、单位快照。生产计划保存产品 `productMaterialId` 和物料需求的 `materialId`。迁移为既有 BOM 和计划补齐档案关联。物料 SKU、单位不可修改；停用已发布 BOM 或未完结计划所用物料时返回业务冲突。
- 集成边界保留于独立连接配置，平台授权与消息适配器后置；未验证之前展示未接入。
- AI 接口 `/api/v1/ai/status`、`/conversations`、`/chat` 使用当前会话读取工作台、BOM 或计划；对话按租户和用户持久化并可删除。`GET/POST /ai/bom-reviews/:id` 读取/生成同版本审查结果，模型 JSON 结果经 schema 和 BOM 行 ID 校验，成功后写审计。只读建议不会改变 BOM 发布规则；无密钥时返回 503。
